## 3. なーたん手動生成の手順（fish audio Web コンソール）

### 3-1. 事前準備

1. ブラウザで [fish.audio](https://fish.audio/) にログイン
2. 課金口座（クレカ）登録済みか確認（未登録の場合は [Settings → Billing](https://fish.audio/app/billing/) で登録）。3案 × 約30秒 = 課金額は**おそらく $0.05 未満**

### 3-2. 3案それぞれの生成手順

**サンプルテキスト**（共通・約30秒・EP01オープニング想定）:

```

子供の頃に図鑑で見た、肉食恐竜から首を守るための盾。
最近の研究では、ちょっと違う見方が出てきているんです。
今夜は、3000万年前の恐竜たちの「もてアピール」について、ご一緒に。
```

**3案 × 同じテキスト**で生成（声紋差だけ比較できるようにする）:

| # | 操作 |
| --- | --- |
| 1 | fish audio Web の「**Playground**」or「**TTS**」画面へ |
| 2 | 上記テキストをテキストエリアに貼り付け |
| 3 | **Voice / Model 選択**で §2-1 案A のモデルを選ぶ |
| 4 | パラメータ: `speed = 0.9` / `emotion = neutral` / `format = mp3` （これらが UI に無ければデフォルトでOK） |
| 5 | 「Generate」→ 生成完了後「Download」 |
| 6 | mp3 を以下のパスに保存 → ファイル名は厳密に: |
|   | `/Users/satonao/Documents/非属人youtube作成/channels/channel_02_dinosaur/assets/voice_samples/ep01_voice_sample_A_<voiceID>.mp3` |
| 7 | `<voiceID>` 部分は fish audio Web の Model URL 末尾英数字（例: `7f92e...`）を入れる |
| 8 | §2-2 案B、§2-3 案C で**手順3〜7を繰り返し**（テキストは同じ・モデルだけ変える） |

**所要時間目安**: 3案あわせて 10〜15分。

## 5. junki 本命と推奨理由

### 5-1. 結論

**junki 本命は 案B（Calm Narrator系）**。

### 5-2. 理由3点

1. **29歳博士キャラの中核（落ち着き × 中音）に最も整合**。案A は淡白に転びがち、案C は文学朗読寄りで「ちょっと違う見方が出てきているんです」の井戸端会議調が出にくい懸念。
2. **自虐セリフを声紋固定したまま `speed` とポーズで制御する方針**（前回提案 §2-3）が、抑揚控えめな B 系統と最も相性が良い。C のように朗読色が強いと、自虐部分でも"朗読してます"感が残り、素っ気なさが出ない。
3. **論文引用「最近の研究では」が井戸端会議調で軽く流せる**柔軟性が B 系統にある。A は逆にニュース読みすぎる懸念、C は重い注釈調に転ぶ懸念。

### 5-3. ただし最終判断はなーたん試聴で

junki の本命は B ですが、**「おやすみ前の大人雑学」というシーン整合では実は C が最強**という可能性も残しています。試聴で C が突き抜けて良ければ C 採用で全然OK。**A が一番なら、それはそれで「淡白な博士」路線として成立**します（こはく人格を少し冷たい方向に再調整するだけ）。

## 7. APIキー再発行時の差し替え手順（短いメモ）

なーたんが fish audio Web でAPIキーを**再発行**した場合の手順:

1. fish.audio Web → [API Keys](https://fish.audio/app/api-keys/) を開く
2. 新キーを発行（「Create New Key」ボタン）
3. 表示された新キーをコピー（**一度しか表示されないので注意**）
4. ローカルの `.env` ファイルを開く:
   - パス: `/Users/satonao/Documents/非属人youtube作成/.env`
5. `FISH_AUDIO_API_KEY=` の右側を新キーに書き換えて保存
6. **旧キーを fish audio Web 側で revoke**（無効化）:
   - 同じ [API Keys](https://fish.audio/app/api-keys/) 画面で旧キーの「Revoke」ボタンを押す
   - これをやらないと旧キーが生きたままになり、漏洩リスクが残る
7. junki 次ターン作業時に新キーで生成テスト1回（任意・本生成前の動作確認）

⚠️ **APIキーをチャットや議事録 .md にコピペしない**。`.env` ファイル内だけに置く運用を守ってください。
