## 2. レビュー観点の分担（yutaka × PM）

manami 初稿に対するレビューを **yutaka と PM の両者で実施**します。観点を分担することで「両者が同じ視点で重複してチェックする」無駄を避け、合計のレビュー時間を圧縮します。

| 観点 | チェック内容 |
| --- | --- |

### 2-2a. ライティング規範6点チェックリスト（PM + yutaka 共通）

manami 初稿を読む際、PM・yutakaの両者が**この6点を順にチェック**します。1点でも欠落していたら REWORK 判定の根拠になります。

| # | 規範 | チェック内容 | 判定NGの例 |
| --- | --- | --- | --- |
| ① | **権威ある文献ベース** | 引用が査読論文・博物館公式解説・教科書級専門書まで降りているか | Wikipediaの孫引き／個人ブログ／まとめサイトを根拠にしている |
| ② | **引用元のさらっと紹介** | 本編中で「○○大学の××教授」「△△年の論文」とナレーションに自然に溶けているか | 引用元が一切出てこない／逆に注釈が重すぎてテンポを壊す |
| ③ | **視聴者への問いかけ** | 「あなたならどう思いますか?」型が3-5回、構成内に分散配置されているか | 一方通行の語りに終始している／問いかけが冒頭1回のみ |
| ④ | **MECE** | 主要な仮説・論点を漏れなく・重複なく整理しているか（例: フリル説で防御説・ディスプレイ説・体温調節説の俯瞰提示） | 1説だけ強調して他説を無視／同じ論点が2回出てくる |
| ⑤ | **中学卒業レベルでわかる** | 専門用語が**初出で1秒で噛み砕かれている**か。抽象語を抽象語で説明していないか | 「角竜類のディスプレイ形質における性淘汰圧が……」のような未噛み砕き連発 |
| ⑥ | **ユーモア** | 29歳女性恐竜博士の自虐＋恋愛比喩が**「8分に1回ペース／10分尺で2回程度・上限3回」**で学術解説の合間に配置されているか（2026-06-02 改訂）。自虐の境界（恐竜オタク○／女性自虐×）厳守。**自虐0回も自然な流れなら許容**（"あるかないか"の境界死守） | 3回以上でキャラ芸人化／NG自虐（容姿・恋愛市場価値）混入／無理矢理ねじ込んで学術解説の流れを切っている |

→ チェック結果は統合フィードバックの冒頭に **「6点準拠状況サマリ」** として記載（◯／△／×）。manami が一目で改善ポイントを把握できる形で返す。

### 2-3. 観点重複時のルール

- 両者の観点が重なる場合（例: 「ナレーター人格が活きているか」は両者の観点に入る）は、**PM の判定を優先**（現場運営はPM管轄のため）。
- ただし「**最終的になーたんに上げる戦略レベルの議論**」は yutaka に集約（PM はそこには独自意見を出すが、決裁ルートは yutaka 経由）。

### 2-4. レビューの実施形式

- **第1パス**: yutaka・PM が**並列で**初稿を読み、各自の観点でコメントを書き込む（manami 初稿ファイル上に直接 or 別ファイルでフィードバック集約）
- **第2パス**: yutaka と PM で**重複部分の調整 + 矛盾解消**
- **manami への戻し**: PM が責任を持って統合フィードバックを作り、manami に返す（窓口の一元化）

## 3. レビューの段階

### 段階1: manami → yutaka + PM レビュー

- **インプット**: manami 台本初稿
- **アウトプット**: 統合フィードバック（PM が責任編集）
- **判定**:
  - **GO**: 軽微な修正のみ → 段階2へ
  - **REWORK**: 構造的修正が必要 → manami 修正稿を待つ
  - **PIVOT**: 切り口自体の再設計が必要 → PM が manami と再設計議論
- **想定期間**: 初稿到着後 2-3日以内に統合フィードバック返す

### 段階2: manami 修正 → 最終レビュー

- **インプット**: manami 修正稿
- **アウトプット**: 確定台本 or 軽微な追加修正指示
- **想定期間**: 修正稿到着後 1-2日以内

### 段階3: 確定台本 → 各職能バトン

- nishi（映像制作）・junki（音声合成・編集）・hina（サムネ・タイトル仕上げ）に確定台本を一斉配布
- 並行作業開始
- 各職能の最適フロー（B-2成果物）が確定している前提

### 段階4: 統合レビュー → 公開判定

- nishi/junki/hina の成果物を統合してプレビュー
- **PM が「公開可否」を判定**（学術精度・映像品質・トーン整合の最終番人）
- yutaka が「対外公開判断」を加える（YouTubeポリシー・チャンネル全体整合・なーたん上申判断）
- なーたんに「公開GO」を上げる（本格運用前のEP01は特になーたん最終承認を必須化）

## 5. レビューで「番人」になる項目（PM の絶対判定）

PM が現場運営の番人として、**他の意見に左右されず守る基準**:

| 項目 | 基準 |
| --- | --- |
| **ライティング規範6点**（なーたん指示 2026-06-02） | §2-2a の6点。1点でも欠けたら REWORK 判定。緩めない |
| **学術精度** | 一次情報優先、推測の明示、最上級表現の限定詞。緩めない |
| **NG語彙** | 「最強・衝撃・ヤバい・サイコパス・闇・禁断」等 → 自動差し戻し |
| **自虐境界** | 「恐竜オタク自虐 ○ ／ 女性自虐 ×」線越え → 自動差し戻し |
| **解剖学的破綻** | 指の本数・歯列・羽毛の有無・運動様式が学術的にアウト → 映像段階で差し戻し（段階4） |
| **過度なキャラ立ち** | 自虐セリフが学術トーンを侵食する分量に達した場合 → 間引き指示 |

これらは yutaka・なーたんからの「公開を急ぐ」圧力があっても**PMが守る**。番人を降りない。

## 7. 失敗パターンと対処

### 7-1. manami 初稿で大幅な方向違い

- **症状**: 学術精度は OK、ただし自虐ギャグの量が多すぎてキャラ芸人化 / 比喩接続が無理筋 / トリケラ求愛ディスプレイ説そのものの解釈が違う
- **対処**: 段階1で **PIVOT 判定** → PM が manami と切り口の再設計議論に1日かける。修正稿ではなく、新規初稿として戻す

### 7-2. nishi の Seedance 採用率が想定より低い

- **症状**: EP01 のトリケラ求愛シーンが Seedance で破綻多発、図解差し替え多めの構成になる
- **対処**: 図解多めでも台本側の流れが成立するか、PM が段階3で判定。台本修正が必要なら manami に少し戻す

### 7-3. fish audio の音声選定で yutaka とPMで意見が割れる

- **症状**: PM「自虐セリフ重視で素っ気ない声」、yutaka「学術解説重視で安定した声」のように観点で割れる
- **対処**: 2-3案のサンプルを揃えて**なーたんに上げる**。なーたんの語感判断を最終的な拠り所にする（ナレーター人格設定もなーたん発案ベースのため）

### 7-4. hina のタイトル提案がトーン軌道に合わない

- **症状**: タイトル候補が学術寄り or 煽り寄りに偏る
- **対処**: 段階3で PM が `02_content_strategy.md` §タイトル構文テンプレと突き合わせて差し戻し
