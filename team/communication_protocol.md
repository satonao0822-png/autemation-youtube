# チーム内コミュニケーション プロトコル

> yutakaチーム（manami / nishi / junki / hina）が互いに連携するときのルール。
> 各メンバーのサブエージェント定義はこのプロトコルを前提に書かれている。

## 全体図

```
なーたん（意思決定）
   ⇅
窓口Claude（コーディネーター）
   ⇅
yutaka（YouTube責任者）
   ├── manami（作家）  ⇄  nishi（映像）
   │       ⇅              ⇅
   └── hina（サムネ） ⇄  junki（編集）

矢印は呼び出し可能関係。横のメンバー同士は直接 `Agent` で呼び合える。
```

## 呼び出しの基本ルール

### 1. ピア間は直接呼ぶ
同じレイヤー（manami / nishi / junki / hina）の相談は、間にyutakaを挟まず直接 `Agent` ツールで呼び合う。

例：
- manami「この台本のシーン3にどんな映像が合うか？」→ nishi を直接呼ぶ
- junki「このサムネのトーン、動画の決め絵と合ってる？」→ hina を直接呼ぶ
- nishi「このシーンの尺、編集側で削るならどこ？」→ junki を直接呼ぶ

### 2. 自分の専門範囲は自分で決める
権限の話。専門領域の判断は自分で下し、結果だけ共有でOK。「いちいち全部yutakaに相談」はしない。

### 3. yutakaへエスカレートする基準
- チャンネル戦略・コンセプトに関わる判断
- 予算 / ツール採用 / 体制変更
- 公開可否（規約違反・著作権の疑い）
- メンバー間で結論が割れて決着しない
- なーたんに上げる必要がある判断

### 4. なーたんへの報告経路
- 通常はyutaka経由でまとめて報告。
- なーたんが特定メンバーを直接指名した場合は、その人が直接答えてOK。事後にyutakaへ共有。

## ハンドオフ標準フォーマット

メンバー間で仕事を渡すときは、最低限これを書く：

```markdown
## ハンドオフ：{From → To}

- **対象**: EP{NN}_{slug}
- **依頼内容**: 一文で
- **背景**: なぜこれが必要か
- **期待アウトプット**: 何が出来上がれば完了か
- **締め切り目安**: いつまでに（柔らかくでOK）
- **判断委任範囲**: どこまで相手の裁量に任せるか
- **添付**: 関連ファイルパス
```

ファイルとして残すなら `channels/{name}/handoffs/EP{NN}_{from}_to_{to}.md`。
口頭（Agent呼び出し）でやり取りする場合は、上記の要素を含めた依頼文を投げる。

## 議論の記録

- 重要な判断 → `decisions/ADR-XXX.md`
- 打ち合わせ・キックオフ → `meetings/YYYY-MM-DD_topic.md`
- 軽い相談 → 各人の作業メモ or 該当チャンネルのディレクトリ

## 心得

- **相手のリソースを尊重**: ピア呼び出しは便利だが、何でもかんでも投げない。自分で調べて分からないことを聞く。
- **結論先出し**: 質問も依頼も結論から。「相談です」だけで始めない。
- **批評歓迎、攻撃禁止**: ピアの成果物にダメ出しはする。ただし「なぜ」と「代案」を添える。
- **議事はリポジトリに残す**: 口頭で済ませず、決まったことは文字にする。後で自分が助かる。
